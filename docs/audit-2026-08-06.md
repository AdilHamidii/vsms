# Bug audit — 2026-08-06

Method: 8 parallel Sonnet agents over disjoint slices of the repo, then one Opus
agent whose brief was to **refute** every finding. Candidates that could not be
made to fail were dropped. Live production DB and the compiler were the
authorities; `CLAUDE.md` was treated as a map of where landmines have been, not
as truth — it was wrong about live figures twice during this audit.

**30 candidates → 21 confirmed, 8 refuted, 1 uncertain.**

Two findings were rediscovered independently by different agents from different
directions, which is the strongest signal in the set: the `sync-5sim` route
seizure (2 agents) and the `delete-account` line orphan (3 agents).

---

## Fix these — ranked

### 1. `sync-5sim` seizes and permanently hides routes it cannot price  🔴 LIVE

`supabase/functions/sync-5sim/index.ts:408`

```ts
if (!pick && !slug) continue;   // only tests the COUNTRY mapping
```

`slug` is the country mapping (`countries.fivesim_country`); `pick` requires the
SERVICE mapping (`services.fivesim_product`). The comment above the guard says it
skips routes with no 5sim product **or** country. It does not. So any route whose
country is 5sim-mapped (60 of 69) but whose service is not falls through to the
write path and is stamped `provider='5sim'`, `status='hidden'`,
`premium_credits=null` (`:419`, `:444-454`) — and counted as `hidden_no_stock`,
i.e. reported as a stockout.

**It is unrecoverable.** `sync-herosms` reads `.eq("provider","herosms")`
(`:125`); `sync-prices` skips `foreignOwned` built from `.neq("provider","smspva")`
(`:127-128`, `:238`). Once a row says `5sim`, only `sync-5sim` will ever look at
it again, and it cannot price it.

Measured live:

| | |
|---|---|
| routes seized | **6,900** across **115** services |
| `fivesim_checked_at` set on all 6,900 | sync-5sim's write path touched every one |
| `retail_credits` non-null on all 6,900 | they were priced, sellable inventory |
| from the 200 newly-seeded services | **0** — rules out "they were always 5sim/hidden" |
| services now `visible=false` | **14** |
| services still visible but stripped to their 9 non-5sim countries | **101** |

The control case is `g2a`, which the owner deliberately excluded from the 5sim
re-home: **60 routes seized and hidden, all 60 in 5sim-mapped countries; 9
surviving on `smspva`/active, none in a 5sim-mapped country.** The split is
exactly the country mapping and nothing else.

Not a regression — the guard is unchanged since `4ac79d4`; it activated when
`fivesim_live` was flipped on.

Dark services: `binance, casa-it, casa-pariurilor, cupidmedia, drug-vokrug, esx,
klarna, parions-sport, publi24, remitly, roomster, sumup, vonage, walletub`.

Fix = the guard, **plus** a repair statement for the 6,900 rows (they cannot
recover on their own).

### 2. `Session.refresh()` wipes the Keychain on *any* error  🔴 LIVE

`VirtualSIM/Auth/Session.swift:59-70` — `catch { await signOut(remote: false) }`
with no discrimination. `signOut` (`:72-84`) nils both tokens and clears all four
Keychain keys. `bootstrap()` calls `refresh()` on **every cold launch** (`:32-41`).

`auth.refresh` throws `URLError` on transport failure, `APIError.http` on any
5xx, `APIError.decoding` on a malformed body — so **cold-launching with no
network signs the user out.** No race required.

(The original finding led with a concurrent-refresh race. That variant is weaker
— GoTrue's refresh-token reuse interval plausibly absorbs it. The transport-error
path is the certain one.)

Fix: only `signOut` on a genuine 400/401 from GoTrue.

### 3. `smspva_health` has no writer — the pre-charge float guard is dead  🔴 LIVE

`poll-active-orders/index.ts:255-268` records only `5sim_health` and
`herosms_health`. `getSmspvaBalance` is imported at `:11` and **never called**.

Live: 5sim and HeroSMS updated 13:33 today; **`smspva_health` frozen at
2026-08-03 11:50, balance $5.26.** The guard (`create-order:613-635`) requires a
reading under 5 minutes old, so for every SMSPVA route it silently never fires.

**1,035 active SMSPVA routes** now charge-then-reserve-then-refund on a dry
balance instead of refusing up front, and `alertLowBalanceBlock` — which only
runs inside that guard — never pages. The balance is below the $7.50
single-order ceiling.

Fix: one `recordBalance` call.

### 4. Two localization holes  🔴 LIVE

- **Tab bar** — `Components/TabBar.swift:14,20-25,49`. `label` is a plain
  `String`, so `Text(item.label)` resolves to the **verbatim** initializer.
  `Home`/`Orders`/`Account`/`Number` are all in the catalog with all six
  translations (fr: Accueil / Commandes / Compte / Numéro) and are reachable from
  nowhere. `eSIM` isn't in the catalog at all.
- **Credit-purchase errors** — `IAP/IAPStore.swift:64,69,102,114,169,174,180,184`
  are bare literals; 6 of the 7 are absent from the catalog entirely. The sibling
  `SubscriptionStore.swift` wraps every equivalent in `String(localized:)`, which
  shows the intent. `CreditsSheet.swift:462`'s `Text(verbatim:)` is *correct* for
  a `String` — the defect is entirely upstream.

The most-seen chrome in the app and the only monetization path, both English for
six locales.

### 5. `check-esim-usage` un-expires a terminal eSIM on view  🟠 LIVE

`check-esim-usage/index.ts:36-41` recomputes `if (profile.activated) status =
"active"` with no terminal-state guard and no `expires_at` check, and the UPDATE
at `:76-77` has **no `.eq("status", …)` claim**. `activated` is a permanent
historical fact.

`EsimDetailScreen.swift:53-57` calls the refresh unconditionally as the first
line of `.task`, and `.active` is a polling state, so the client then re-confirms
it every 8s.

**8 rows are `status='expired'` with `activated=true` and `expires_at` set** —
exactly the failing population. Rows *with* `expires_at` self-heal within 15
minutes; the `depleted → active` variant does not, because
`expire_esim_orders()` keys only on `expires_at` and 12 rows have it NULL.

Harm: a user is told a dead data plan is live, while abroad.

### 6. `delete-account` releases nothing but SMS orders  🟠 DORMANT (fires on first line customer)

`delete-account/index.ts` is 58 lines and queries **only `orders`** (`:32-36`)
before `deleteUser` (`:52`). Zero references to `phone_lines`,
`line_subscriptions`, Telnyx, `esim_orders` or `email_orders`.

- `phone_lines.user_id` **cascades** (`20260805170000:95`), so the row — and with
  it `provider_number_id`/`connection_id`/`credential_id`, the only pointers to
  the rented Telnyx resource — is destroyed with no release call. $1/month
  continues forever.
- `line_subscriptions.user_id` has **no FK** (`:205-211`), deliberately, so it
  survives. `begin_line_rental:549-556` then refuses the returning user with
  `subscription_bound` because their new user id ≠ the bound one. **No path
  anywhere rebinds `user_id`** — the lockout is permanent without manual SQL.
- Apple keeps charging $9.99/month regardless; deleting our account does not
  cancel an Apple subscription.

The asymmetry is exactly backwards: the tombstone survives and blocks the
legitimate owner, while the billed resource vanishes.

`esim_orders`/`email_orders` have the same gap at lower cost (cents; HeroSMS
auto-refunds a mailbox at ~21 min). One file, three product lines — fix together.

The orphan sweep in `release-lines:204-205` would catch it, but is gated on
`app_config.line_orphan_release_enabled`, which does not exist. That default-off
is **deliberate** (`:278` prints "set … to true after checking") and defensible —
the defect is the missing release, not the flag.

### 7. Inbound calling is broken twice over  🟠 DORMANT (do before first sale)

- **`TELNYX_IOS_PUSH_CREDENTIAL_ID` is not configured.** `supabase secrets list`
  returns only `TELNYX_API_KEY`, `TELNYX_MESSAGING_PROFILE_ID`,
  `TELNYX_PUBLIC_KEY`. `_shared/telnyx.ts:479-494` spreads
  `...(opts.pushCredentialId ? {…} : {})` — it omits the field silently rather
  than failing, so every credential connection is created without VoIP push
  capability. `mint-line-token:121` still returns `inbound_ready: attachedOk`,
  derived only from the voice attach, never from push-credential presence.
- **Inbound calls are never recorded.** `record_line_call` has exactly one
  caller, `begin-line-call:100`, outbound-only. `currentCallId` is written only
  at `CallController.swift:158` inside `placeCall`; the VoIP push handler
  (`:437-461`) never sets it, and `report()` guards on it at `:220`. So an
  inbound call consumes no allowance, reaches no history, and leaves nothing for
  the CDR sync to match — contradicting the advertised 100-minute hard stop.

Neither failure is observable from the server.

### 8. `settle_stale_calls` settles a still-connected call at zero seconds  🟠 DORMANT

`20260806100000:333-358` selects on `allowance_settled=false AND created_at <
now()-360min` with **no `status` and no `ended_at` predicate**, then settles from
`coalesce(duration_seconds,0)` — which is NULL mid-call, giving `'missed'` and
`billed_seconds=0`. `settle_call_claim` (`20260805170000:1036-1046`) then refuses
forever, and `sync-telnyx-cdr:52-56` drops the row from `pending`, so the real
CDR can never be applied.

### 9. The missing `cancel_order_claim`  🟡 LATENT — never fired

`cancel-order:198-241` and `create-order:681-718` (`failOrder`) split the status
claim and the refund across two round-trips with a TypeScript rollback.
`grep -rn cancel_order_claim supabase/` → **zero hits**; the four claim functions
that exist cover expiry, eSIM and email. CLAUDE.md's own rule says a TS rollback
cannot fix this "because the process is gone."

**But:** a live query for terminal orders with a charge and no matching refund
row returns **zero rows**. The window is one Postgres round-trip at the end of a
request. Fix it on the next money-path pass — it is silent and permanent if it
ever fires, not urgent.

## Refuted — do not act on these

| finding | why it is not a bug |
|---|---|
| "Nothing caps a call in progress" | `settle_line_allowance` (`20260805170000:485-492`) computes `actual - reserved`; overshoot is **explicitly permitted** and the table comment at `:1078-1081` says so. The hard stop gates *new* calls by design. |
| "Inbound SMS dropped while `suspended`" | `suspended` is an intentional service cutoff, not a preserved-service hold — `:724-728` says the edge function revokes the telephony credential, "what makes suspension real rather than client-side theatre". In-app copy matches: `LineScreen.swift:424-432` promises inbound only for `.pastDue`. |
| "Three ASSN transitions lack the provisioning guard" | Unreachable. `reclaim_lapsed_lines()` (`20260806100000:98-104`) sweeps `provisioning` older than 15 min to `failed`, on an active `*/15` cron — so the window is ≤30 min after purchase, and a monthly subscription cannot be past-due 30 minutes after it is bought. |
| "`providerOrder()` ignores ownership-first" | Ran the settling query the finding itself proposed, all three providers: active routes where the owner's own codes are null/empty → **zero rows**. `create-order:399` also refuses non-active routes. |
| "Out-of-order notifications resurrect a revoked subscription" | **Nothing reads `line_subscriptions.state`.** The only two reads of the table select `user_id` for the binding check. No consumer, no consequence. |
| "`sync-esim-plans` lacks a 999-credit clamp" | Adding one would **introduce** a bug: `create-esim-order:17-19,60` derives `maxCostUsd` *from* the credit count, so clamping would put the ceiling below wholesale and turn honest plans into `margin_too_low`. The absence preserves the lockstep. |
| "eSIM purchase TOCTOU" | Documented deliberate policy at `create-esim-order:55-79` — fail closed on a bad price, open on a failed lookup. SMSPool exposes no price cap; no code change removes that. |
| "WaitingScreen says 'Active rental'" | It is `Text("Active rental")` — a literal, so it **is** localized in all six locales. A terminology preference, and the colliding product isn't in any shipped build. |

Also ruled out during the audit:

- **The CDR deploy is not stale.** `sync-telnyx-cdr` deployed 74s *before* its own
  fix commit, which looks exactly like the classic stale-bundle trap. It is live:
  `app_config.telnyx_cdr_shape` — a key the fix introduced — was written 4s after
  deploy, and `telnyx_cdr_faults` has stayed frozen at the old `record_type:
  "call"` 400 across ~30 subsequent cron runs.
- **The two Swift concurrency warnings in the VoIP path are not races.** The
  registry is `PKPushRegistry(queue: .main)` (`CallController.swift:128`), so the
  callback genuinely runs on main; the compiler just can't prove it. They will be
  errors under Swift 6.
- **No deploy or config drift.** 39 function dirs, 39 deployed; all 15
  cron-gated functions carry `verify_jwt = false`; the only 3 no-JWT functions
  without a cron-secret check are the 3 legitimate webhooks.
- **Margin lockstep holds exactly** for all providers (5sim 0.04/10.0, HeroSMS
  0.025/16.0, SMSPVA 0.05/8.0 against `NET_USD_PER_CREDIT` 0.40), and the eSIM
  pair is byte-identical between its two files.

## What the false positives had in common

29% of candidates did not survive. The recurring errors are worth knowing,
because they are what an automated sweep of this codebase will produce again:

1. **Reading a code shape as a reachable state.** The guard really is written
   that way; the input that exploits it does not exist. Neither agent that
   proposed a settling query actually ran it.
2. **Treating a documented decision as a defect.** Three refutations contradict
   an explicit in-code comment, twice within twenty lines of the cited line.
3. **Proposing a fix that breaks an invariant documented elsewhere.**
4. **Overstating permanence.** "Stuck forever" had an End button eight lines
   away; "money loss" had never once occurred in the entire order history.
5. **Trusting `CLAUDE.md`'s live numbers.** It understated the eSIM bug's
   reachability — the file says 10 of 11 orders have `expires_at` NULL; the table
   says 8 expired rows have it set.
